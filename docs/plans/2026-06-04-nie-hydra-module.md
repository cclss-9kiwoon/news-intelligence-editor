# NIE Hydra 모듈 기획안

> NIE를 독립 SPA에서 Hydra 플랫폼 내 캠페인 기반 아티클 자동 생산 모듈로 재설계한다.

## 기존 기획안과의 관계

`docs/plans/2026-05-28-nie-workflow-improvements.md`의 Phase 1~3(전문 수집, 프롬프트 설정, 이미지 소싱)은 **파이프라인 내부 엔진 스펙**으로 유지. 이 기획안은 그 엔진 위에 씌워지는 **캠페인 + 칸반 레이어**.

---

## 구조

```
Hydra
├── 배포 그룹: allkpop (회사 단위)
│   ├── 연결된 채널: X, 인스타, YouTube...
│   └── 캠페인들
│       ├── "tier 3 아티클"
│       ├── "관광 아티클"
│       └── "K-pop 컴백 속보"
│
├── 템플릿
├── 캘린더
├── 결제
└── 설정
```

### 계층

| 레벨 | 역할 | 예시 |
|---|---|---|
| **그룹** | 회사/매체 | allkpop, 스포츠조선, TechCrunch |
| **캠페인** | 아티클 종류 | "tier 3 아티클", "관광 아티클", "K-pop 컴백" |
| **태스크** | 개별 기사 건 | "BTS 뷔 솔로 2집 발매" |

## 캠페인 설정

캠페인 = "어떤 종류의 아티클을 어떻게 쓸 것인가"를 정의하는 단위.
**여기가 가장 정교해야 함.** CMS마다, 매체마다, 아티클 종류마다 원칙이 다르므로 결과물 퀄리티와 일관성을 여기서 결정.

### 캠페인 설정 항목

```
캠페인: "allkpop tier 3 아티클"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📌 소스 설정
├── RSS 소스 (어디서 기사를 가져올지)
│   ├── 스포츠조선 RSS
│   ├── 뉴스1 연예 RSS
│   ├── 한국경제 연예 RSS
│   └── + 소스 추가
├── 토픽 필터 (어떤 주제만 가져올지)
│   ├── 키워드: 컴백, 앨범, 차트, 콘서트...
│   └── 제외 키워드: 정치, 경제...
└── 자동 선별 기준
    ├── 최소 매체 수: 2개 이상이 다뤄야 태스크 생성
    └── 시간 윈도우: 24시간 이내 기사만

📌 아티클 포맷 (CMS별로 다름)
├── 에디터 역할: "K-pop 전문 매체의 시니어 에디터"
├── 발행 가이드
│   ├── 문체/톤
│   ├── 기사 구조 (리드문 → 본문 → 마무리)
│   ├── 목표 분량
│   ├── 인용/출처 표기 원칙
│   └── 미확인 정보 처리 방식
├── 작업 지침 (교차검증, 팩트 처리 규칙)
├── 금지 표현
└── 레퍼런스 기사 (최대 5개, 우리 매체 실제 기사)

📌 출력 설정
├── 출력 필드 (headline, body, tags, imagePrompt, sourceFacts...)
├── 언어 (한국어/영어/자동 번역)
└── 이미지 처리 (원문 이미지 수집 여부)
```

**모든 설정에 기본값 프리셋 제공 + 사용자 수정 가능 + 기본값 복원.**

기본값 상세는 엔진 스펙(`2026-05-28-nie-workflow-improvements.md`) Phase 2 참조.

## 칸반 보드

캠페인 안에서 태스크(개별 기사 건)가 칸반으로 자동 흐름.

```
┌─────────────┬─────────────┬─────────────┬─────────────┐
│   서칭       │  소스 검수   │ 아티클 제작   │ 결과물 검수  │
│             │             │             │             │
│ ┌─────────┐ │ ┌─────────┐ │ ┌─────────┐ │ ┌─────────┐ │
│ │ 뷔 솔로  │→│ │ 뷔 솔로  │→│ │ 뷔 솔로  │→│ │ 뷔 솔로  │ │
│ │ 2집 발매 │ │ │ 원문+서브│ │ │ 초안생성 │ │ │ 검수대기 │ │
│ └─────────┘ │ │ 4건 수집 │ │ │ 완료    │ │ └─────────┘ │
│ ┌─────────┐ │ └─────────┘ │ └─────────┘ │             │
│ │ 에스파   │ │             │             │             │
│ │ 컴백    │ │ ┌─────────┐ │             │             │
│ └─────────┘ │ │ 에스파   │ │             │             │
│ ┌─────────┐ │ │ 전문추출 │ │             │             │
│ │ 리사    │ │ │ 진행중   │ │             │             │
│ │ 파리행사 │ │ └─────────┘ │             │             │
│ └─────────┘ │             │             │             │
│  ▲ 계속 생성 │             │             │             │
└─────────────┴─────────────┴─────────────┴─────────────┘
         자동              자동             자동           사람
```

### 각 단계 상세

#### 1. 서칭 (자동)

**입력**: 캠페인 소스 설정 (RSS + 토픽 필터)
**하는 일**:
- RSS 폴링으로 기사 수집
- 범용 추출기로 전문 추출 시도
- 같은 주제 기사 묶기 (클러스터링 — 백그라운드 로직)
- 토픽 필터 매칭

**태스크 생성 조건**:
- 클러스터 내 매체 수 ≥ 캠페인 설정 최소치
- 토픽 필터 매칭됨
- 시간 윈도우 이내
- 이미 태스크 생성된 주제와 중복 아님

**태스크 카드 표시**:
```
📰 BTS 뷔 솔로 2집 발매
   원문: 스포츠조선 | 서브 3건
   30분 전
```

**다음 단계로 자동 이동 조건**: 태스크 생성 즉시 → 소스 검수

#### 2. 소스 검수 (자동)

**하는 일**:
- 원문 + 서브 소스 전문 추출 완료 확인
- 전문 추출 실패 시 폴백 (네이버 #dic_area → description 대체)
- 이미지 수집 (본문 내 이미지 URL + 캡션)
- 최소 품질 체크: 전문 수집된 소스가 N건 이상인지

**태스크 카드 표시**:
```
📰 BTS 뷔 솔로 2집 발매
   전문 수집: 4/4건 완료
   이미지: 6장 수집됨
```

**다음 단계로 자동 이동 조건**: 전문 수집 완료 (또는 타임아웃 후 있는 것만으로 진행)
**탈락 조건**: 전문 수집된 소스 0건 + description도 불충분

#### 3. 아티클 제작 (자동)

**하는 일**:
- 캠페인 설정(에디터 역할, 발행 가이드, 작업 지침, 금지 표현, 레퍼런스)으로 시스템 프롬프트 조립
- 수집된 전문들을 유저 프롬프트로 전달
- LLM 호출 → 초안 생성 (headline, body, tags, imagePrompt, sourceFacts)
- 프롬프트 조립 상세는 엔진 스펙 Phase 2-E 참조

**태스크 카드 표시**:
```
📰 BTS 뷔 솔로 2집 발매
   초안 생성 완료
   본문 1,024자 | 태그 6개 | 이미지 6장
   sourceFacts 8건
```

**다음 단계로 자동 이동 조건**: LLM 응답 수신 + JSON 파싱 성공

#### 4. 결과물 검수 (사람)

**편집자가 하는 일**:
- 초안 확인 (headline, body, summary)
- sourceFacts로 팩트 대조
- 이미지 후보에서 선택 (출처 판단은 사람이)
- 필요 시 본문 편집
- 최종 판단: 발행 / 수정 후 발행 / 폐기

**태스크 카드 표시 + 액션**:
```
📰 BTS 뷔 솔로 2집 발매
   ┌──────────────────────────────┐
   │ 헤드라인: 정국, 7월 솔로 2집... │
   │ 본문: (1,024자)               │
   │ 📋 sourceFacts 8건            │
   │ 📸 이미지 후보 6장             │
   ├──────────────────────────────┤
   │ [✏️ 편집] [✅ 발행] [🗑 폐기]  │
   └──────────────────────────────┘
```

**발행**: 연결된 채널(X, 인스타 등)로 배포 → Hydra 기존 배포 파이프라인과 연결
**폐기**: 사유 태그 선택 (품질 부족, 주제 부적합, 중복 등) → 캠페인 자동 선별 학습에 활용 가능

## 파이프라인 동작 방식

```
캠페인 활성화
    │
    ▼
RSS 폴링 루프 (설정된 간격으로 계속 돌아감)
    │
    ├── 새 기사 발견 → 클러스터링 → 태스크 생성 조건 충족?
    │   ├── Yes → 서칭 칸반에 태스크 카드 생성
    │   └── No → 무시 (기준 미달)
    │
    ├── 태스크 → 소스 검수 → 전문 추출
    │
    ├── 전문 완료 → 아티클 제작 → LLM 초안 생성
    │
    └── 초안 완료 → 결과물 검수 → 편집자 대기
```

**동시에 여러 태스크가 각 단계에 있을 수 있음.** 태스크 A가 결과물 검수에 있는 동안 태스크 B는 아티클 제작 중이고 태스크 C는 서칭에서 방금 생성됨.

**캠페인은 여러 개 동시 운영 가능.** "tier 3 아티클" 캠페인과 "관광 아티클" 캠페인이 각각 독립적으로 돌아감.

## Hydra 통합 포인트

| 영역 | Hydra 기존 | NIE 모듈이 사용 |
|---|---|---|
| 그룹 | 배포 그룹 (회사) | 그대로 사용 |
| 채널 | X, 인스타, YouTube... | 발행 시 배포 대상 |
| 캘린더 | 발행 일정 | 결과물 검수 완료 → 캘린더에 발행 예약 |
| 템플릿 | 콘텐츠 템플릿 | 캠페인 설정 프리셋으로 활용 가능 |
| 결제 | 구독/결제 | LLM API 비용, 전문 추출 API 비용 |

## 구현 순서

```
Phase 0: 엔진 (기존 기획안 Phase 1~3)
├── 전문 수집 안정화 (범용 추출기 + 네이버 폴백)
├── 프롬프트 설정 시스템 (PromptConfig + 레퍼런스 기사)
└── 이미지 수집

Phase 1: 캠페인 구조
├── 캠페인 CRUD (생성, 설정, 삭제)
├── 캠페인 설정 UI (소스, 포맷, 가이드, 프롬프트)
├── 캠페인 ↔ 그룹 연결
└── 캠페인 설정 저장/로드

Phase 2: 칸반 파이프라인
├── 태스크 모델 (상태: searching → source_review → producing → final_review)
├── 서칭 → 소스 검수 자동 전환
├── 소스 검수 → 아티클 제작 자동 전환
├── 아티클 제작 → 결과물 검수 자동 전환
├── 칸반 보드 UI
└── 태스크 카드 상세 뷰 (초안 + sourceFacts + 이미지 + 편집)

Phase 3: 결과물 검수 & 발행
├── 편집자 검수 UI (편집, 발행, 폐기)
├── Hydra 배포 파이프라인 연결 (채널로 발행)
└── 캘린더 연동 (발행 예약)
```

## 현재 NIE 코드 처리

현재 독립 SPA(`src/App.tsx`, `src/components/*`, `src/state/*`)는:
- 엔진 로직(`src/lib/*`) → 그대로 재사용
- UI 컴포넌트 → Hydra UI 체계에 맞게 재작성
- State 관리 → 캠페인/태스크 모델로 재구성
- 독립 SPA 셸(`App.tsx`, `Header.tsx` 등) → Hydra 모듈로 대체
