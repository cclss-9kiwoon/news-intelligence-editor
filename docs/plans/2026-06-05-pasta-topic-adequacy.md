# Pasta ② 적합성 — 캠페인 주제 정의 + AI 의미판단

> 문제: 좁히기가 literal 포함키워드뿐 → 검색결과 다 탈락(119→0) 또는 비우면 firehose. 중간 없음.
> 워크플로: 캠페인 = 주제별 파이프라인(컴백·신보 / 일상 / 사건사고). 각자 검수·표현 다름.
> 해법: 캠페인에 "주제 정의" 필드 + ②에서 AI가 주제 부합을 의미로 판단.

## 핵심
- 검색어 = 넓게 가져오기(현행)
- **캠페인 주제 정의(신규)** + **② AI 적합성** = 진짜 좁히기 (캠페인별 다르게)
- literal 포함키워드 = 보조 옵션 유지(꼭 그 단어 필요할 때만)

## 데이터
- `Campaign.settings.intent?: string` (또는 topicReview.intent) — 자연어 주제 정의.
  예: "K-pop 컴백·신보 발매 소식" / "아이돌 일상·예능·SNS" / "연예계 사건·사고·논란"
- 비우면 적합성 AI 판단 생략(현행 firehose 동작 = 하위호환).

## ② 적합성 판단 (AI)
- judge: 기사(제목+내용)가 (캠페인 intent + 그룹 character/방향)에 **부합**하나?
  → 적합 / 부적합 / 애매(uncertain).
- 적합 → ②-B 제작가능성으로. 부적합 → 컷(다른 캠페인이 잡을 수도). 애매 → 보류 or 통과(보수적: 보류).
- excludeTopics(제외 AI)와 같은 자리(②). 적합성=포함 의미판단, excludeTopics=제외 의미판단. 한 번의 judge로 묶어 호출 가능(비용 절감).
- 검수 LLM = topicReview.llm(단계별 LLM, 싼 모델 권장).

## 흐름 (캠페인별 주제 라우팅)
같은 그룹의 여러 캠페인(컴백/일상/사건사고)이 각자 검색→수집→②에서 자기 주제만 선별.
- 컴백 캠페인 ②: intent="컴백·신보" → 컴백 기사만 적합.
- 일상 캠페인 ②: intent="일상·예능" → 일상만 적합.
한 기사가 여러 캠페인 주제에 걸치면 각 캠페인이 독립 판단(중복은 ownSiteDedupe/④ 중복게이트가 처리).

## 분담
- NIE_개발(로직): ② 적합성 judge(intent+그룹방향 부합, 적합/부적합/애매) — excludeTopics judge와 통합 호출 권장. topicReview.llm 사용.
- Engineer(UI): 캠페인 ② 설정에 "주제 정의" 자연어 입력칸(+예시 placeholder, 그룹 character 참고 힌트). 포함키워드는 "보조(선택)"로 라벨 정리.
- 공유: Campaign.intent 스키마 선합의.

## 범위
v1: intent 필드 + ② AI 적합성 judge(부합 판단) + UI 입력. literal 포함키워드 보조 유지. G2(제작가능성)와 함께 ②를 완성.
