## 3. 화면별 명세

### S1. 가입 / 로그인
- 조직 생성 또는 초대 수락.

### S2. 조직 대시보드
- 프로젝트 목록 + 새 프로젝트.
- 빌링(구독/팩) — 조직 레벨.

### S3. 프로젝트 (= 옛 배포그룹)
- 헤더: 프로젝트명(allkpop), 30일 발행 현황.
- **연결 채널**: allkpop.com + 소셜(X/IG/Threads/TikTok/YT/LinkedIn) + 블로그(WordPress/Ghost/Tistory/네이버…). 채널 추가/인증.
- **캠페인 목록** + 새 캠페인.
- 캘린더(예약 발행 전체 뷰), 템플릿.

### S4. 캠페인 상세 — **3탭** (핵심 화면)
탭 A · **수집 설정**
- 소스(RSS/네이버), 검색어/쿼리, 주제 정의(intent), 제외 주제.
- 비-LLM 사전필터: civic/노이즈 컷 + kpop allowlist. 봇차단 도메인.
- 페이싱: 한 건씩(head-of-line 방지), 단일소스 minMedia.

탭 B · **제작 칸반** (옛 news2 / NIE ①~④)
- 컬럼: ①기사찾기 → ②주제검수 → ③기사작성 → ④최종검수 → **발행함**.
- LLM 4단계(주제판단/스토리생성/검수/번역), 프로바이더 Gemini/OpenAI/**위임(B모드, 크레딧0)**.
- 클러스터링, 워터마크/저작권 검증, 비용추적/예산가드, 처리중 카드 글로우.

탭 C · **발행**
- "발행함" 기사 → 채널별 초안 자동 변환(템플릿).
- 채널 선택, 즉시/예약 발행, 미리보기.

### S5. 발행 로그 / 캘린더
- 발행됨/예약됨/실패 추적.

## 3-1. 화면·메뉴 구조 (3단 스코프 — Engineer 전달 완료 2026-06-11)

메뉴가 평평하게 섞이지 않게, 들어간 깊이(스코프)별로 분리.
★ 원칙: **"프로젝트/캠페인"은 메뉴 항목이 아니라 현재 위치(컨텍스트)**. 상단 바 브레드크럼+드롭다운으로 표시·전환. 사이드바엔 자기 이름 반복 금지("프로젝트메뉴" 같은 자기참조 항목 X).
- 상단 바(항상): [조직명] 프로젝트▾(현재) > 캠페인▾(현재)
- 사이드바 = 현재 위치의 하위 내용물만

**1단계 전역(조직)** — 메뉴: 홈·조직설정·빌링·로그아웃
- 홈 = 조직 대시보드: 프로젝트 카드 목록 + [새 프로젝트] + 전체 발행추이 + 빌링요약
- 빌링 = 조직설정으로

**2단계 프로젝트(=옛 배포그룹)** — 메뉴: 대시보드·캠페인·채널·캘린더·설정
- 채널 = 프로젝트 레벨 / 설정: 채널관리·기본LLM·브랜드/톤·템플릿·멤버권한
- **프로젝트 메인(대시보드) 구성 (= 관제탑):**
  1. 헤더: 프로젝트명+목적 한 줄+30일 발행수+[설정]
  2. 요약 지표 카드줄: 오늘발행·제작중·**검수대기(🟡사람확인)**·예약됨·폐기
  3. **캠페인 목록(메인 컬럼)**: 카드=이름·카테고리·자동/수동·ON/OFF·오늘발행/대기·마지막발행·[열기] + [새 캠페인]
  4. 발행 파이프 미니현황(프로젝트 합): 제작중→검수대기→발행함→발행됨 + 막힘 알림
  5. 연결 채널 상태: 채널별 연결/오류 + 오늘 발행수
  6. 발행 캘린더 미니: 다가오는 예약 + 최근 발행
  7. 할 일/알림: 검수대기·채널오류·키/배포 필요
  - 레이아웃: 좌=캠페인목록+파이프 / 우=채널·캘린더·할일. 검수대기 강조.
- **프로젝트 생성 화면:** 프로젝트명·목적/설명·기본언어·브랜드톤 기본값 (+선택: 채널 연결) → [만들기]→메인
- **프로젝트 설정 화면(섹션):** 일반(명·목적·언어·보관/삭제) / 채널(=채널관리) / 기본LLM(프로바이더·모델·단계별) / 브랜드·톤 기본값 / 템플릿(채널별 양식) / 멤버·권한
- ★ 상속: 프로젝트 설정=기본값 → 캠페인이 상속·오버라이드 (group→campaign 패턴)

**1단계 홈(조직 대시보드) 구성:**
- 상단: 조직명 + [+새 프로젝트]
- 프로젝트 카드 그리드: 프로젝트명·목적·오늘발행/대기·캠페인수·🟡검수대기 배지·[열기]
- 조직 전체 요약: 발행 추이 그래프·채널 합계·빌링(구독/사용량)
- 프로젝트별 할 일 롤업

**수동/자동 = 캠페인 내 모드 (워크벤치 존치, 설정 공유):**
- 한 캠페인 = 1설정(주제·필터·문체·검수). 자동(auto_process ON)이나 워크벤치(수동 뷰)나 **같은 캠페인 설정 공유**.
- 워크벤치 = 캠페인 하위 수동 작업 뷰(별도 설정 X). 옛 "수동 워크벤치(뉴스1)" 전역/독립 → 캠페인 하위로 흡수.
- 수동 모드 단계 이동 = 드래그앤드롭(사람이 카드 넘김, NIE 패리티 #12).

**캠페인 [제작] 탭(칸반) 구성:**
- 컬럼: ①기사찾기→②주제검수→③기사작성→④최종검수→발행함
- 카드: 제목·소스 매체수·클러스터·상태배지·처리중 글로우(한 건씩)
- 상단: 자동진행 ON/OFF·현황·[폐기함]/[현황]
- 카드 클릭→상세: 원문들(멀티소스)·생성 본문·검수 리포트(신호등)

**채널 관리(프로젝트 레벨) 구성:**
- 채널 목록 상태별: 🟢연결/⚪미연결/🔴오류·토큰만료 + 마지막 발행·오늘 발행수
- 연결 방식: OAuth류(X/IG/Threads/TikTok/YT/Blogger/Tumblr)=OAuth팝업 / API키류(allkpop/WP/Ghost/dev.to/Hashnode)=키입력(allkpop=create/api.php+X-API-KEY, 키는 allkpop-dev CLI 발급) / 수동류(Medium/Velog/Brunch/네이버/Tistory)=사이트 이동 안내
- 채널별 기본설정(F 프로젝트 기본값): 카테고리·태그·작성자·해시태그·대표이미지 (캠페인이 오버라이드)
- 헬스: 토큰만료·발행실패·레이트리밋 경고

**캠페인 [발행] 탭 구성:**
- 발행함 큐(승인 기사 리스트)
- 기사 선택→채널별 미리보기(allkpop/X/IG 각 양식)
- 발행: 즉시/예약+채널선택 (E정책 상한·금지시간 자동 반영)
- 발행 로그(발행됨/실패/예약됨+재시도) · 캘린더 뷰

**3단계 캠페인** — 설정은 ★NIE식 **칸반 단계별**(A~F 섹션 탭 아님): ①기사찾기=수집·소스언어·필터 / ②주제검수=판정·LLM / ③기사작성=문체·이미지·출력언어·LLM / ④최종검수=검수8종 / 발행=채널·정책. 각 단계(칸반 컬럼)에 config 귀속.
- 옛 news2 = "제작" 탭으로 흡수
- ★LLM 설정 단일화(확정 6/12): **기본 LLM 1세트(프로바이더·API키·모델) = 전 단계 기본.** 단계별(②③④번역) 오버라이드 = 접이식 "고급 설정"(기본=기본LLM 상속). 키 입력칸 = 기본 LLM 섹션 1개(=상위). 단계별 4개 노출 폐기. 이 단순화 = 키 저장버그 수정과 동일 화면·동일 작업.

## 3-2. 캠페인 명세 (인수조건 — 캠페인 = 에디터 1명)

캠페인 1개 = 독립된 에디터. 설정 = 그 에디터의 성격·규칙.

**A. 무엇을 다룰까 (수집 필터)**
- 카테고리 다중선택(컴백/신보·차트·시상식·콘서트·데뷔·컬래버·글로벌…)
- 포함: 아티스트/키워드 allowlist
- 제외(촘촘히): 사생활·열애·사건사고·정치·루머 토글
- 신선도: 최신 N시간/일 이내만 / 무관
- 교차검증: 사건당 최소 매체 수 N

**B. 어떻게 쓸까 (문체)**
- 톤(객관/팬친화/분석) · 길이·구조 · 관점(주관 허용도) · 언어(KO/EN, 번역) · 인용·출처 규칙 · 금지표현/브랜드가이드

**C. 검수 기준 (④ 게이트)**
- **표현 중복(텍스트 유사도)**: (a)생성문이 원문 매체 표현을 너무 베꼈나=표절 (b)우리 과거 기사 문구와 너무 똑같나=자기복제
- 주관성 과다 · AI스러움 · SEO(제목/메타/키워드/구조) · 사실/환각 · 민감표현 · 발행포맷

**D. 이미지**
- 워터마크/저작권 컷 · 출처(소속사공식/whitelist) · 해상도·비율 · 채널별 크기

**E. 발행 정책**
- 수동/자동 · 주기·양(시간당/일 상한) · 발행 금지 시간대 · 채널 선택

**F. 채널별 설정**
- CMS(allkpop/WordPress/Ghost): 카테고리·태그·대표이미지·SEO메타·작성자
- X/Instagram/Threads/TikTok/YouTube: 각 포맷(길이·해시태그·이미지필수·스레드화) → 채널별 양식 변환 템플릿

**워크플로 (게이트):**
1. 수집: 1000 풀 → A 필터 → 통과만
2. ②주제검수: 주제적합 + **주제(소재) 중복** 사전체크(이 사건 이미 다뤘나=자사/교차캠페인) → "쓴다" 면 진행
3. 본문추출: 같은 주제 여러 매체 ≥N개
4. ③재생산: B 문체대로 여러 전문 종합 새 기사 + D 이미지
5. ④최종검수: C 전부 점검 → 통과=발행함
6. 발행: 수동/자동(E) → 자동이면 F 양식으로 CMS/SNS

★ 중복방지 이중 게이트 (레벨 다름):
- ②사전 = **주제 중복** (같은 소재/사건 이미 다뤘나 → 작성 전 차단, 헛수고 방지)
- ④최종 = **표현 중복** (생성문이 원문 표절 or 우리 과거기사 자기복제 → 텍스트 유사도)

### D-1. ★이미지 저작권 정책 (확정 2026-06-17, 법적 리스크 대응 — 최우선)

## 0-5. ★주제 선별 설계 개선 — 벡터 유사도 기반 (확정 6/12)
**문제:** 현 ① 사전필터가 intent/카테고리에서 단어 추출→literal 매칭(키워드 SELECT). 의미를 못 잡아 "제대로된 주제" 누락(주제 맞는데 단어 다름) + 오통과(단어 맞는데 주제 다름). 구기운: autosquad 풀은 벡터 유사도 검색용 설계, 단어 SELECT 아님.
**개선 설계:** 캠페인 intent(+카테고리) → 임베딩 → 벡터풀(digest_global_raw_chunks 임베딩 컬럼)에서 ★의미적 유사 top-N 검색(pgvector `<=>`) → exclude_topics/source_lang 필터 → ②LLM 정밀판정.
**전제:** 풀 임베딩과 동일 임베딩 모델로 intent 임베딩해야 비교 가능 → autosquad 임베딩 모델 확인 필요(지상/구기운). Hydra는 read-only client.
**범위:** 키워드 prefilter를 유사도 기반 후보선별로 교체. ② LLM 판정은 유지(별도 ②실패 버그는 병행 수정). 큰 변경 → hydra-pm 커밋 승인.

## 0-6. ★② 주제(소재) 중복 방지 — 추가 (확정 6/12)
**문제:** 같은 사건을 이미 발행했는데 또 클러스터링돼 ③ 작성=헛수고+중복발행. 정본 3-2 이중게이트 중 ★②사전(주제중복)이 미배선.
**설계:** ②주제검수(또는 ①→② 승급) 시점에 클러스터를 ★이미 발행/제작된 기사와 대조 → 같은 사건이면 재작성 차단(discard, "topic_dup").
- 매칭: 대표제목+엔티티 겹침 OR 임베딩 유사도(벡터유사도 작업과 연계). lookback window(예 7일) 내 같은 캠페인/조직 발행분 대상.
- ④표현중복(표절/자기복제=생성TEXT 유사도)과 구분: ②=주제(소재) 중복(작성 전 차단), ④=표현 중복(작성 후).
**캠페인 설정:** 주제중복 방지 ON/OFF + lookback 기간 + 엄격도(유사도 임계).
**담당:** 백엔드(Engineer). pipeline ② 단계 + published/stories 대조.

## 0-7. ★주제선별 개선 확정안 (6/12, OpenAI 키 불필요)
